# 0.8.29 资源占用与卡顿检查



## 实际观察



本机约32秒采样中，桌宠PowerShell进程占用约2555MB私有内存；该短时区间没有持续上涨。仅凭这个区间不能确认无界内存泄漏，也不能排除更早积累。异常桌宠和自动换肤监测已暂停，未重新启动默认应用。



用户描述为长时间后台运行后切回黑屏、其他程序也卡顿。本轮没有重启真实桌面应用做长时间复现，不能声称黑屏已被彻底消除。



## 已修正



- 整合版桌宠不再遍历聊天窗口的UI Automation完整可访问性树；隐藏或最小化的宿主也不再进行就绪探测。原路径在界面未识别为就绪时可反复扫描；该路径与异常内存的因果关系尚未通过堆转储证实。

- 桌宠保存最多60个资源样本；连续3次30秒采样超过512MB私有内存即暂停，不自动重启。音频播放器、窗口消息钩子和临时进程对象在退出时释放。

- 启动流光缓存冻结的画笔和路径采样，减少每帧创建对象。离屏绘图基准测得每帧分配由919319字节降到137350字节，绘制命令耗时由2.641ms降至0.095ms；这是本机微基准，不是整机GPU帧率。

- 旋转阳光层由150vmax正方形改为120vw×140vh；仅按原生应用窗口前后台判断：前台持续播放，页面/输入框失焦不影响；后台移除装饰DOM并取消动画，前台重建一层。检查间隔为2.5秒，保留单次检查互斥和并发请求合并；查询本身耗时会增加响应延迟。移除重复绘制且缩放的背景层，静态背景始终保持同一尺寸，光线和花瓣单独恢复。原有4K背景、配色和流光周期保留。

- 并发连接检查共享一个进行中的检查，避免多页面轮询各自启动PowerShell进程。

- 自动监测、额度查询和额度工作进程启动失败后停止，等待手动重试；缺失CLI和零字节Windows执行别名不会被当成额度程序调用。

- 已有受管理窗口时复用；预览不叠加多个启动窗口。主窗口45秒未就绪时结束等待并提示，不再永久占着动画和持续检查。

- 额度查询失败在一分钟隔离测试中没有自动重试；缺失CLI与Windows空别名检查通过。

## 托盘退出后重新启动



失败日志显示启动被9335端口占用拦截，动画随失败任务被清理。对于主动启动时未能确认归属的监听端口，最多等待3秒释放并重新核验专用进程，再启动一次；持续占用不启动、不结束占用进程。普通Inspect不等待也不启动。隔离模拟验证了短暂占用、持续占用和状态检查三种情形；未反复启动实际应用。
